# Why `.shai-hulud-allow` has entries, and why it has no comments

`.github/scripts/shai-hulud-marker-scan.sh` filters its findings with:

```sh
grep -vE -f "$ALLOW_FILE"
```

## The file must contain patterns only — no comments, no blank lines

`grep -f` treats **every** line of the file as a pattern, and an **empty line is a regex that matches every line**. One blank line therefore filters out *all* findings, and the scan reports `OK — no IoC markers` while detecting nothing.

Verified directly:

| `.shai-hulud-allow` contents | planted `bsc-dataseed` marker |
|---|---|
| *(no allowlist)* | detected, exit 1 |
| **one blank line** | **silently ignored, exit 0** |
| one scoped pattern | detected, exit 1 |

That is why the rationale lives in this file and the allowlist itself is three bare regexes. **Do not add comments or blank lines to `.shai-hulud-allow`** — it will disable the gate without failing anything.

## The entries

All three are `ccxt`, all flagged by TIER2 (`trongrid` / `aptoslabs` / `bsc-dataseed` — drainer C2/RPC hosts):

- `js/src/prediction/myriad.js`
- `dist/cjs/src/prediction/myriad.js`
- `dist/ccxt.browser.min.js` (and its `.map`)

ccxt ships prediction-market support that legitimately embeds public blockchain RPC endpoints:

```js
'rpcUrl': 'https://bsc-dataseed.binance.org/'
```

That is a public Binance Smart Chain data-seed node. It is exactly the class of string a wallet drainer carries, which is why the pattern exists — but here it is inherent to what ccxt does, and ccxt is a first-order dependency of this CLI.

**Each entry is a blind spot.** The filter drops the whole matching line, so these paths are suppressed for *every* tier, not just the pattern that misfired. The two `myriad.js` files are small and reviewable; the browser bundle is a single multi-megabyte line this CLI never loads (we bundle ccxt's CJS entry point). Re-check these on major ccxt upgrades.

## Why the monorepo never needed this file

Under pnpm, every `node_modules` entry is a symlink, and the scanner's `grep -r` **does not descend into symlinks** (`-R` would). So in `tokenbot-org/data-models` the `node_modules` scan root matched essentially nothing — dependency source was never actually scanned.

This repo installs with npm, which creates real directories, so it is the first to scan dependency source for real. **Fewer findings in the monorepo means less coverage, not a cleaner tree.**
